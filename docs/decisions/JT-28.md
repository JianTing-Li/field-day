# JT-28 decisions ("Something changed?" in your own words, 2026-11-02)

### D-JT28-1 — Organizers say what changed in their own words, and confirm FieldDay's reading
- **Date / owner:** 2026-11-02 · JT (decided with the human)
- **Problem:** "Something changed?" took one change at a time from a fixed list. Text under "Something else" went to
  the agents as background only, so "500 people showed up, and I have no money" got no answer at all. "Time doesn't
  work" couldn't take a new time, so moving a session to the morning meant editing the whole brief.
- **Decision:**
  - One text box takes any number of changes; shortcuts (space, ground, rain, new time, group size, equipment) add
    the common ones without typing.
  - `POST /changes/read` turns the text into a list of `ChangeItem`s and changes nothing. With real agents and an API
    key it is one model call (forced tool output, checked against the contract, the text passed as data); otherwise,
    or if that call fails, keyword rules read it. A note the model writes for something the rules can act on is
    replaced by the rules' reading, so the model never refuses a change FieldDay can make.
  - Every part of the text gets an answer. What FieldDay can change: a report (space, ground, rain, time), a new start
    window, date, group size, length, missing equipment, exercises to leave out, or a park to drop. Anything else is
    a note with a plain reply (money, permits, staff, messaging, bookings, medical advice are out of scope per the
    PRD). Out-of-range values become notes that say the limit ("FieldDay plans for up to 500 people").
  - The organizer sees the list, can remove lines, and confirms. `POST /changes/apply` then saves brief changes and
    drafts one new plan (reports in the same list still count), or re-checks reports and looks for a fix, or only
    keeps notes. Notes are stored as `change_reports` of kind `other` with the reply.
- **Why confirm first:** a misread "500" would quietly re-plan for the wrong group. One tap is cheaper than that.
- **Limits:** reads count separately from agent runs (40 per visitor per hour, 400 a day, real agents only).
