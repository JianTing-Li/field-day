# JT-22 decisions (follow-up to JT-07: confirmation layout)

### D-JT22-1 — Space and surface confirmations are tied to a workout layout
- **Date / owner:** 2026-10-28 · JT
- **PRD section:** §3 "Validation Policies" (space/surface), §4 "Organizer confirmation resolves only the stated check"
- **Decision:** `OrganizerConfirmation` gains an optional `layout`. When a confirmation is recorded, the harness
  sets it to the layout the current plan needs (template layout, changed by the last adaptation that sets
  `resulting_layout`, the same rule as the workout rules in D-023), but only when the confirmation is for the
  current plan's park and time; otherwise it is null. A confirmation resolves a `space_surface.*` check only for a
  plan with the same layout; null never resolves one. Other checks match on check, park and time as before
  (D-012, D-016). This fixes a running-lane confirmation passing a later stationary plan (and the reverse).
  Interim: in JT-09, confirmations should become `organizer_confirmation` evidence (`category` = layout) read by
  the workout rules, replacing this matching; the organizer task or confirm request then needs to name the layout.
- **Status:** in use
